# FitProject — спецификация MVP

Надстройка над WHOOP: приложение и сайт, которые забирают твои данные через официальный API
и дают то, чего нет в родном приложении.

## Проблема: что не так с приложением WHOOP

Взято из форума WHOOP Community, обзоров и отзывов в сторах.

| Боль | Что мы делаем |
|---|---|
| Журнал — только фиксированный список поведений, свои добавки и привычки не залогировать. Через API журнал не отдаётся | Свой журнал: свободный текст + `#теги`, быстрые теги в один тап, запись из Telegram одной фразой |
| Цифры есть, объяснений нет: «почему recovery 34%?» | Инсайты: влияние каждого тега, сна, нагрузки и загруженности календаря на recovery и HRV следующего дня, с размером эффекта и уровнем доверия |
| Нет графиков трендов, например температуры кожи; неудобно смотреть длинную историю | Тренды за 30/90/180/365 дней по всем метрикам, скользящее среднее, сравнение с личной нормой |
| Встроенный AI-коуч плохо настраивается | Свой коуч на Claude, видит всю историю, журнал и календарь; отвечает по-русски и по делу |
| Данные заперты в приложении | Всё хранится в своей БД, экспорт в CSV |
| Нет связи с жизнью вне браслета (встречи, дедлайны, поздние созвоны) | Календарь (ICS: Google, iCloud, Outlook): встреч в день, часы занятости, поздние события → в инсайты |

## Функции MVP (вечер-два)

1. **Подключение WHOOP** через OAuth 2.0 (API v2), refresh-токены, первичная загрузка всей истории, синхронизация по вебхукам и раз в час.
2. **Сегодня:** recovery, HRV, пульс в покое, сон, strain, отклонение от личной 30-дневной нормы, рекомендация целевого strain и времени отбоя.
3. **Тренды:** графики метрик за выбранный период.
4. **Журнал:** заметки по дням с тегами.
5. **Инсайты:** что влияет на восстановление именно у тебя.
6. **AI-коуч:** чат по своим данным (нужен `ANTHROPIC_API_KEY`; без него работает упрощённый режим на правилах).
7. **Календарь:** ICS-ссылки.
8. **Telegram-бот:** утренняя сводка, как только посчитан recovery; `/today`, `/week`; любой текст → заметка в журнал; `/ask` → вопрос коучу; недельный отчёт по воскресеньям.
9. **Демо-режим:** 180 дней синтетических данных, чтобы всё работало до получения ключей WHOOP.

## Этап 2

- Нативное iOS-приложение (SwiftUI) и виджеты WidgetKit (recovery на экране «Домой» и экране блокировки). Бэкенд уже отдаёт `/api/widget` и принимает Bearer-токен.
- EventKit-календарь прямо с iPhone вместо ICS.
- Push-уведомления (APNs).
- Хостинг (Railway, Fly.io или VPS) и Postgres вместо SQLite.
- Доступ для других: регистрация в WHOOP (в dev-режиме до 10 пользователей, дальше нужно одобрение WHOOP).

## Архитектура

```
WHOOP API v2 ──OAuth / webhooks──▶ backend (FastAPI, Python)
                                     ├─ SQLite (все данные, мультипользовательская схема)
                                     ├─ sync: history + webhooks + hourly
                                     ├─ insights / coach (Claude API)
                                     ├─ calendar (ICS)
                                     └─ telegram bot (long polling, тот же процесс)
                                            │  REST /api/*
                     ┌──────────────────────┴───────────────────┐
                web (Vite + React + TS)                iOS (SwiftUI + WidgetKit) — этап 2
```

## Ограничения WHOOP API

- Нет журнала, посекундного пульса, Stress Monitor, Healthspan, данных Strength Trainer.
- Вебхуки есть только для sleep, recovery и workout; для cycle/strain их нет, поэтому strain подтягивается при периодической синхронизации.
- Лимиты: 100 запросов в минуту, 10 000 в сутки.
- В режиме разработки приложение доступно максимум 10 пользователям WHOOP.
